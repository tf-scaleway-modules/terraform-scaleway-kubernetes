## Why

The organisation `terraform` standards (store v2.1.0) require every module to work with both OpenTofu and Terraform: one `required_version = ">= 1.11.0"`, both CLIs pinned in `mise.toml`, and a CI job that validates with Terraform. This module still declares `>= 1.10.0`, pins a bare `opentofu = '1.11'`, and has no Terraform validation job.

## What Changes

- **BREAKING**: `required_version` goes from `>= 1.10.0` to `>= 1.11.0` in `versions.tf` and `examples/*/versions.tf` (`examples/minimal` says `>= 1.10.7`). Consumers need OpenTofu or Terraform >= 1.11.0.
- `examples/complete/versions.tf` and `examples/minimal/versions.tf` keep the scaleway constraint equal to the root's (`~> 2.89`, already the case); `examples/minimal` drops the stale `// Open tofu 1.10.7` comment.
- `mise.toml`: `opentofu` `'1.11'` becomes `'1.13.10'`; `terraform = '1.17.2'` is added.
- `.gitlab/release.yml`: `validate:opentofu` image `ghcr.io/opentofu/opentofu:1.11` becomes `:1.13.10`; new `validate:terraform` job (`hashicorp/terraform:1.17.2`) right after it, validating the root and every `examples/*`; added to `create:release` `needs:`.
- `.pre-commit-config.yaml`: `terraform_fmt`, `terraform_docs` and `terraform_tflint` have no `args` today; each gets `--hook-config=--tf-path=tofu` so they keep running OpenTofu now that `terraform` is installed too.
- `openspec/config.yaml`: `terraform` store `ref: v1.2.6` becomes `v2.1.0` (other refs unchanged); the context line `required_version >= 1.10.0` becomes `>= 1.11.0`.
- `.github/workflows/ci.yml` and `release.yml`: `tofu_version` `"1.11.0"` becomes `"1.13.10"` (the `mise.toml` pin); no new GitHub job (there is no Terraform step).
- README floor badge `Terraform-%3E%3D1.10` becomes `%3E%3D1.11`.
- Docs outside the terraform-docs markers: `AGENTS.md` names OpenTofu >= 1.11.0 and Terraform >= 1.11.0 and adds `terraform init -backend=false && terraform validate` to the format/validate command; the README gains a compatibility sentence and an "Upgrading from v3 to v4" note.
- No input, output, resource, state or provider-constraint change. No construct that `terraform validate` rejects is used (checked: no `lifecycle { enabled }`, no `language {}`). The `check` block in `main.tf` is kept; both tools support it.

Release level (`terraform-versioning`): **major**, because the `required_version` floor is raised. Upgrade note: "consumers need OpenTofu or Terraform >= 1.11.0".

Inputs/outputs whose type, default or meaning change: none. Files whose content changes: `versions.tf`, `examples/complete/versions.tf`, `examples/minimal/versions.tf`, `mise.toml`, `.gitlab/release.yml`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `.pre-commit-config.yaml`, `openspec/config.yaml`, `AGENTS.md`, `README.md` (outside the markers; the generated `requirement_terraform` row is regenerated by terraform-docs).

State: nothing new lands in state; no secret-bearing input.

Standards applied: `terraform-providers` (Version constraints), `terraform-module-structure` (Tooling), `terraform-repo-gitlab-ci` (Terraform validation job, Release depends on validation), `terraform-repo-mise`, `terraform-repo-precommit` (Terraform hooks run tofu), `terraform-versioning`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `module-contract`: the "Tool and provider version constraints" requirement states the floor `>= 1.10.0`; it becomes `>= 1.11.0` for OpenTofu and Terraform.

## Impact

- Consumers on OpenTofu/Terraform 1.10.x can no longer init the module; they upgrade the CLI first. Provider constraint (`~> 2.89`) is unchanged.
- CI gains one job; release now waits on it.
- The GitHub mirror workflows follow the `mise.toml` pin (`Hooks and CI use the pinned tools`).
