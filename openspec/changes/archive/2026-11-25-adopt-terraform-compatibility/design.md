# Design

## Context

Standards store `terraform` v2.1.0 makes OpenTofu and Terraform both first-class (`terraform-providers`, `terraform-module-structure`). The module has `>= 1.10.0`, `opentofu = '1.11'`, a single `validate:opentofu` job, and Terraform hooks without `--tf-path`. Provider arguments and resources do not change.

## Goals / Non-Goals

**Goals:**
- One `required_version = ">= 1.11.0"` honoured by both tools, pinned toolchains in `mise.toml`, CI proving Terraform compatibility.

**Non-Goals:**
- No new resource, argument, input or output; no provider bump (the scaleway constraint stays `~> 2.89`); no unit-test suite change (it stays on `tofu test`, per `terraform-testing`); no `.tofu` file or `language {}` block.

## Decisions

- **Floor 1.11.0** (`terraform-providers`): the first release of both tools with ephemeral values and write-only arguments; below the newest stable OpenTofu, so no lock-out. Major release per `terraform-versioning`.
- **Exact pins** (`terraform-repo-mise`): `opentofu = '1.13.10'`, `terraform = '1.17.2'`; CI image tags copy them (`terraform-repo-gitlab-ci`).
- **`validate:terraform`** follows `validate:opentofu`, runs `terraform init -backend=false && terraform validate` in the root and each `examples/*`, and is listed in `create:release` `needs:` after `validate:opentofu`.
- **Hooks** `terraform_fmt`, `terraform_docs`, `terraform_tflint` get `args: [--hook-config=--tf-path=tofu]` (`Terraform hooks run tofu`); today they have none, so with `terraform` installed they could pick the wrong CLI. The hook rev is not touched.
- **GitHub mirror workflows** pin `tofu_version` to the `mise.toml` value (`1.13.10`); no job is added.
- **README badge**: the floor badge follows the new floor (`%3E%3D1.11`).
- **`check` block kept**: supported by both tools.
- **Docs**: README compatibility prose and the upgrade note live outside `BEGIN_TF_DOCS`/`END_TF_DOCS`; the generated requirement row is regenerated by pre-commit.
- **Examples**: `examples/complete` (`>= 1.10.0`) and `examples/minimal` (`>= 1.10.7`) both move to `>= 1.11.0`; their scaleway constraint already equals the root's.

## Risks / Trade-offs

- Consumers on 1.10.x break: accepted, declared as a major bump with the upgrade note.
- Terraform 1.17.2 may reject something OpenTofu accepts: checked in a scratch copy (never in the repo, to keep `registry.terraform.io` out of the lock file) before commit.
- No state or plan impact: no resource change, a second plan stays empty.
