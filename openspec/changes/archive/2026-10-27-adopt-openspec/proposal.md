## Why

This module has never used a spec-driven workflow: its contract lives only in
`variables.tf`, `outputs.tf`, the README and the commit history. The
organisation plans changes with OpenSpec (engineering standards in the
`quality`, `repository` and `terraform` stores). This is the **first adoption**
of OpenSpec in this repository (there was no Agent OS to migrate from).

## What Changes

- Add `openspec/config.yaml` (stores pinned via the terraform-module profile,
  module context, artifact rules) and `AGENTS.md` / `CLAUDE.md` routing.
- Install the `openspec-*` skills for Claude Code (`.claude/skills/`) and OpenCode
  (`.opencode/skills/`).
- Add `scripts/openspec-setup.sh`, the `spec-validate` / `spec-setup` mise tasks and
  the `validate:specs` CI job (`.gitlab/specs.yml`).
- Record the module's **current, released behaviour** as baseline specs
  (capabilities below). No `*.tf` file, example or test changes; the module
  contract is unchanged, so the release is a semver **patch** (tooling only).
- `CHANGELOG.md` stays generated by git-cliff from commit subjects; it is not
  curated by hand.
- No `tests/` directory exists yet; new behaviour adds `tests/main.tftest.hcl`.

## Capabilities

### New Capabilities
- `module-contract`: Terraform/OpenTofu and provider constraints, no provider/backend blocks, input names, types, defaults, and the output set
- `cluster`: the Kapsule/Multicloud cluster, its feature flags, auto-upgrade, autoscaler and OIDC configuration
- `node-pools`: node pools created from `node_pools`, scaling, labels, taints, user data, upgrade policy and independent pool upgrades
- `kubeconfig-outputs`: kubeconfig-derived outputs, their sensitivity and the provider configuration helpers

### Modified Capabilities
None.

## Impact

- Repository tooling and documentation only; module inputs, outputs, resources
  and state are untouched (nothing new lands in state).
- Semver: patch (terraform-versioning), no input or output changes.
- Consumers pinning `?ref=vX.Y.Z` are unaffected.
